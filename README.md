# 站点营造 · 公交线网站台建设与三维街区推演

Vue 3 + three.js 的单页系统，覆盖从新建站台申请、过程式街区推演、候选站点编排，
到工单派发、现场施工、质检验收与主管复盘的完整闭环。全部数据存于浏览器 localStorage，
无需后端。

## 运行

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # 生产构建
npm test           # 确定性 / 站距约束单元测试
npm run verify     # 端到端验收（需先 npm run dev；用本机 Chrome 无头运行）
```

## 七个界面

| # | 路由 | 名称 | 职责 |
|---|---|---|---|
| 01 | `/apply` | 新建申请 | 线路走向、站距上下限（默认 300–800m）、首末班时间、预算档位、种子锁定 |
| 02 | `/simulate` | 三维推演 | 种子驱动的沿线街区体量/立面，单栋编辑与单栋重生成 |
| 03 | `/stations` | 站点编排 | 候选站点自动排出、里程剖面、超 300–800m 标红、增补候车站 |
| 04 | `/dispatch` | 工单分派 | 按片区把工单分给施工员，支持整片区均衡派工 |
| 05 | `/field` | 现场施工 | 施工员只看本人待办：录入尺寸、站亭朝向、上传现场照片后提交 |
| 06 | `/qc` | 质量抽检 | 按验收标准抽查；盲道＜40% 或遮挡视线直接打回并写原因；三次返工锁单 |
| 07 | `/board` | 主管看板 | 按人统计完成量与返工率、工单状态构成、线路总览图、导出 |

## 关键实现

### 1. 确定性生成（同一 seed 结果完全一致）

- `src/core/rng.js`：`hash32`（FNV-1a + 雪崩混合）+ `mulberry32`。
- 每条随机流都由 `seed + 用途 + 对象 ID` 派生，**不使用 `Math.random` 参与任何几何/参数**。
- 楼栋布局（位置、间距）与单栋参数（层数、面宽、进深、立面、色调）使用**互相独立的随机流**，
  因此单栋改动不影响其他楼栋；街区中也不写入时间戳，指纹只由种子与参数决定。
- 指纹：`districtFingerprint()` 对全部楼栋的 `id/层数/面宽/进深/风格/色调/坐标/朝向` 做哈希，
  在三维页顶部实时显示，便于肉眼核验。

### 2. 单栋重生成不冲掉手工修改

建筑对象结构：

```js
{ id, base: {…种子原型…}, overrides: {…运营手工字段…}, nonce }
```

- `resolveBuilding(b)` 返回 `{...base, ...overrides}`，**手工字段永远优先**。
- “单栋重生成”只递增该栋 `nonce` 后重算 `base`，`overrides` 原样保留。
- 整线重生成 / 换种子 / 改密度时，`carryOverOverrides()` 按楼栋 ID 回填 `overrides` 与 `nonce`。
- “应用改造”只提交与当前生效值不同的字段，不会把未改动项钉成覆盖。

### 3. 站距校验与调整

- `proposeStops()` 用“下限 + 配水式分配余量”的算法，保证每段严格落在 `[315, 785]`，
  站数自动受线路长度约束（`minStops ≤ N ≤ maxStops`），不会出现负站距。
- 超出 `[300, 800]` 区间一律标红（`spacingLevel()` 返回 `bad`）。
- “增补候车站”在超标段中点插站，把长站距拆成两段合规站距，并保持既有工单绑定。

### 4. 工单与质检规则

- 工单绑定 `workerId`，施工员端按身份过滤，只显示本人待办。
- 质检不通过项：盲道连续率 < 40%、遮挡视线、尺寸偏差 > ±50mm、朝向不符、照片不足，
  全部写入 `qc.reasons` 并在工单台账导出。
- `reworkCount` 每次打回 +1；达到 3 次自动置为 `locked`，需主管在质检页确认解锁
  （解锁后计数清零）。

### 5. 数据与导出

- `localStorage` 键：`bus-stop-studio.v1`，首次进入即落盘，深度 watch 去抖写入。
- 导出：线路清单 CSV（含站距校验列、预算、首末班）、工单台账 CSV（含返工次数、质检原因、锁单原因）。
