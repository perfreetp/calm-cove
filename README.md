# 隧道机电图档平台 · 通风系统

面向隧道机电设计院的通风系统图档制作与交付平台。客户下单建项目，主管按区段派活，制作员在分层平面图上修改要素并送审，系统自动质检，主管逐条审核，通过后打包生成 DXF + PDF + 校验报告。

## 快速开始

```bash
npm install
npm run seed        # 生成演示数据（3 个项目，约 4.5 万个要素）
npm run dev         # API :4173 + 前端 :5173（Vite 代理 /api）
```

生产模式：

```bash
npm run build
npm start           # Express 提供 /api 与 dist 静态页面，端口 4173
```

测试：

```bash
npm test            # 22 项：质检规则、送审/退回/返工、区段锁定、交付包完整性、API 契约
```

## 功能

### 项目看板
- 项目进度、区段通过率、要素总量、待处理问题、累计返工、超期风险
- 风险模型：`剩余区段 / 4（日审 4 区段） + 返工次数 × 0.5 天` 对比交付倒排天数；超期为 red，工期不足为 high
- 客户端下单：隧道长度、车道数、洞线数、交付日期、图纸规格（A0–A3），下单即生成全量要素

### 绘图工作台（`/projects/:id/draw`）
- **分层平面图**：暖通 / 电气 / 土建 / 标注四层可独立开关，各层显示要素计数
- **数万要素渲染**：每种「图层+类型」一个 Mesh，实例矩阵走 thin instance 缓冲；单项目 2.9 万要素在 1:500 下约 618 个可见要素、单向绘制调用数不到 10。正交相机 + 视口矩形剔除，视口外要素不进入实例缓冲
- **分级显示（LOD）**：
  - 缩放稀于 **1:5000** → 概览：区段条带 + 每区段射流风机数量柱，不画单机与管线
  - **1:500 及更近** → 展开单机、风阀、风管、桥架、检测器与桩号标注
  - 级别由当前视宽换算出的出图比例（96 dpi 折算）决定，HUD 实时显示 `1:xxxxx`
- **点选**：点击要素在右侧弹出编号、型号、所属区段（可跳转定位）、上下游要素链（同类同洞线按桩号相邻）
- **框选**：拖拽矩形批量选中，可整批改挂接区段或取消挂接
- 键盘：`V` 选择、`R` 框选、`F` 全景、滚轮缩放、空格拖动平移、`Esc` 清除

### 质检
| 检查项 | 规则 |
| --- | --- |
| 风机间距不足 | 同一洞线同一安装线的相邻射流风机中心距 < 6.0 m |
| 传感器漏挂 | CO / 能见度检测器 `mounted = 0` 或未挂接区段 |
| 区段编号重复 | 项目内区段编号冲突（含 2 处、3 处以上） |

质检结果按「检查类型 + 区段 + 要素集合」稳定去重：重跑时已豁免/已整改的结论保留，缺陷消失的问题自动置为「已失效」，不产生重复条目。可逐条定位、标整改或确认豁免（豁免必须填写说明并写入审计）。

### 送审与审核
- 制作员提交区段 → 系统自动跑质检并快照该区段问题 → 生成送审记录（轮次自增）
- 主管逐条审：通过 → 区段锁定；退回 → **必须填写原因**，区段回到返工中且 **返工次数 +1**（只增不减，审核通过不改变计数）
- **通过前必须先清零该区段的未处理问题**：区段仍挂有 open 问题时不允许通过，主管须先「标整改」或「确认豁免」，避免已签收的图纸里带着没人能再动的缺陷
- 同一送审记录不可二次处理
- **已通过区段被锁定**：要素修改、批量改挂接区段、重新送审都会被拒绝（409），需主管退回后才能继续；退回不额外增加返工次数

### 交付包
一次打包生成并附 SHA 校验和清单：

| 文件 | 内容 |
| --- | --- |
| `*_土建层.dxf` 等 4 个 | 分层 DXF（AC1015，$DWGCODEPAGE=ANSI_936，块定义 + INSERT/LINE/CIRCLE/TEXT） |
| `*_通风系统_全图层.dxf` | 合并全图层 |
| `*_通风系统图_A1.pdf` | 1:500 系统展开图，按里程分段成册；每页含区段统计表、本页问题清单、图例、会签栏、图签与校验章 |
| `*_校验报告.md` | 结论（通过 / 待整改）、问题清单、DXF 结构校验、区段交付清单 |
| `*_区段要素清单.csv` | 每区段要素总数与分类统计 |
| `*_要素明细.csv` | 全量要素（编号/型号/桩号/挂接/上下游） |
| `*_交付清单.json` | 机读清单：每文件大小与校验和、区段清单、DXF 校验结果 |

交付包生成后即时校验：DXF 会被重新解析确认实体数与图层；PDF 使用内嵌中文字体（SimHei 子集）。**已通过区段中仍存在未整改且未豁免的问题时，交付包标记为「待整改」并计入阻断项；已「标整改」或「确认豁免」的问题不再阻断交付。**

### 包内检索
交付包详情页可按区段或关键字检索要素清单（编号 / 型号 / 区段），并查看包内文件校验和与 DXF 结构校验结果。

## 技术栈

- **前端** SolidJS + @solidjs/router，Babylon.js 9（正交相机、thin instance、自绘 2D overlay）
- **后端** Express 5 + `node:sqlite`（同步 API，WAL）
- **导出** DXF 自写 ASCII 生成器；PDF 用 PDFKit + SimHei 子集字体
- **几何生成** 确定性种子 RNG：同一 seed 永远生成同一套要素，质检结果与交付包可复现

## 中文字体

PDF 出图需要中文字体。打包时按以下顺序查找：

1. 环境变量 `PDF_CJK_FONT` 指向的字体文件
2. `server/assets/NotoSansSC.ttf`（可自行放入，未随仓库提交）
3. 系统字体：`C:/Windows/Fonts/simhei.ttf`、`msyh.ttc`、`NotoSansSC-VF.ttf`，macOS `PingFang.ttc`，Linux Noto CJK

仓库不附带系统字体文件（许可证限制）；部署到无系统中文字体的服务器时，请放入 Noto Sans SC（OFL 许可）或设置 `PDF_CJK_FONT`。
