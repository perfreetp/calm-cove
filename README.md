# 青澜 · 水库赛艇训练航道与赛事图层系统

面向赛艇队教练组与赛事观众的双端 Web 应用。教练端编排训练科目、复核自动判读、分配赛事赛道；观众端只读查看整片水域的分层平面图、训练轨迹与赛事日分组。

技术栈：**Svelte 5（runes）+ SVG + D3（d3-zoom / d3-selection）+ TypeScript + Vite**。

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
npm run check    # svelte-check，当前 0 error / 0 warning
```

演示数据首次启动时以确定性种子生成并写入 `localStorage`；右上角头像菜单可「恢复演示数据」重新播种。

## 七个界面

| # | 端 | 路由 | 说明 |
|---|-----|------|------|
| 1 | 观众 | `#/viewer/overview` | 水域总览：分层平面图、图层面板、轨迹点选、单艇回放 |
| 2 | 观众 | `#/viewer/schedule` | 训练日程：已发布科目列表 + 详情（航道、浮标、风向、趟次） |
| 3 | 观众 | `#/viewer/raceday` | 赛事日：预赛/决赛分组名单、赛道分配、当日流程 |
| 4 | 教练 | `#/coach/sessions` | 训练编排：新建/编辑科目，航道多选、浮标区间、风向圆盘、发布 |
| 5 | 教练 | `#/coach/review` | 判读复核：异常趟次标黄 + 截图、逐条复核为有效/作废并写原因 |
| 6 | 教练 | `#/coach/races` | 赛事编排：拖拽分道、冲突自动提示、发布/撤回 |
| 7 | 教练 | `#/coach/stats` | 统计报告：分段时间、偏航率、出勤矩阵 |

默认进入观众端；左侧「当前视角」切换角色，或按 <kbd>R</kbd>。快捷键：<kbd>1</kbd>–<kbd>4</kbd> 切页、<kbd>L</kbd> 操作记录、<kbd>Esc</kbd> 关闭浮层。

## 地图实现要点

**分层**：水深分层（3/6/12/20 m 等深面）、岸线、测量网格、航道线、浮标、码头设施、训练轨迹、注记，八层独立开关，另可「仅看此层」。

**缩放 1:2000 – 1:200**：比例尺分母 `N = 3779 / k`（按 96 dpi 的 CSS 像素实算），缩放范围由适配视图到 `N ≈ 200`。四段细节：

| 层级 | 比例尺 | 绘制内容 |
|------|--------|----------|
| overview | > 1:4400 | 仅水域、航道线、浮标 |
| far | 1:1900–4400 | + 航道编号 |
| mid | 1:1000–1900 | + 浮标编号、码头注记 |
| near | 1:480–1000 | + 艇位与编号（起点线船形标记）、判读图钉 |
| close | < 1:480 | + 艇号全称、分段点、地物名称、起终点注记 |

**上万轨迹点**：每条趟次预处理四档折线串（22 / 60 / 170 / 全量采样），渲染为**单条 `<path>`**，而非逐点节点。LOD 切换走纯 CSS（`[data-lod] .trk.l0 { display:none }`），平移缩放期间不重建任何几何。种子数据共 38 趟 / 21,682 个轨迹点。

**屏幕恒定尺寸**：pan/zoom 时向容器写入 `--inv: 1/k`，浮标半径、航道虚线、注记字号、门线线宽全部用 `calc(Npx * var(--inv))`，因此不会随放大变成巨型色块。

**点选与高亮**：对 130 点抽样做最近距离命中测试（阈值 11 screen px / k），命中后轨迹描粗、分段点出现、右侧检查器展开；<kbd>Shift</kbd> 多选对比。

**回放**：单趟按自身时间轴插值位置，`requestAnimationFrame` 推进，支持 1× / 2× / 4× 与拖动进度条；回放期间强制「near」细节层级。

## 自动判读规则

| 判定 | 规则 | 取值 |
|------|------|------|
| 偏航 | 任一点偏离航道中线 | > 3.00 m（≥ 5 m 记为严重） |
| 抢航 | 越过起航线时刻相对发令 | < 0 s（< −0.5 s 严重） |
| 漏标 | 通过 250 m 标志线时横向偏移 | > 6.75 m（半个航道） |

异常趟次在列表内标黄、带 `AUTO-JUDGE` 截图（内联 SVG，含航道带、±3 m 虚线、轨迹、最远点圈注与纵向窗口标尺）。教练逐条填原因后判「有效 / 作废」，或对当前筛选批量处理；每条决策写入操作记录（操作人 + 时间 + 原因分类 + 说明）。

统计口径：作废趟次不计入均值，待复核趟次单独标注；500 m 配速按每趟距离归一后取均值，因此 500 m 与 2000 m 课次可以同表比较。

## 赛事编排

- 预赛 / 决赛分组，每场 6 条赛道，拖拽艇只卡片或下拉框分配，赛道间可交换。
- **冲突检测**（`src/lib/race.ts`）在每次改动后实时重算：
  - 同一场次内同一艇只占两条赛道 → 硬冲突
  - 同日两场比赛同一开赛分钟 → 硬冲突（同一水域无法同时起航）
  - 同一阶段（预赛↔预赛 / 决赛↔决赛）同一艇只重复入列 → 硬冲突
  - 组别与本场不符、入列不足 2 艇 → 冲突项
- 冲突不会阻止保存，但在编排页顶部红条列出，且「发布」前应有交代；艇只卡片与赛道行同时标红。
- 发布后观众端赛事日立即可见；草稿只出现在教练端，并在观众端以「N 场分组尚未发布」提示。

## 数据与状态

`src/lib/` 下按职责拆分：

- `types.ts` — 领域模型（World / Session / Run / Race / AuditEvent…）
- `geo.ts` — 种子随机、Catmull-Rom 曲线、多边形内点、时间格式化
- `world.ts` — 水库几何：岸线控制点、按 thalweg 收缩的等深面、6 条 14 m 航道、54 枚浮标、码头
- `sim.ts` — 轨迹合成：速度剖面（起航加速 / 途中衰减 / 冲刺）、分形横向摆动、注入偏航/漏标高斯包
- `judge.ts` — 判读规则与 SVG 截图生成
- `trackRender.ts` — 四档折线缓存、按时间取位置
- `seed.ts` — 10 节课 / 38 趟 / 6 场赛事 / 操作记录
- `race.ts` — 赛道冲突扫描
- `store.svelte.ts` — 全局可写状态，所有写操作同时追加审计事件
- `viewStore.svelte.ts` — 视图状态（角色、图层、选择、回放）

持久化：每次写入 350 ms 防抖后整体序列化到 `localStorage`（`qinglan.rowing.v1`），读取失败或隐私模式无存储时回落到种子数据，页面仍可正常使用。

**操作记录**覆盖科目新建/修改/发布/结课/删除、复核与批量复核、赛事分配/改时/发布/撤回/重命名/新建、轨迹上传与系统自动判读，每条含操作人、角色、时间、目标与摘要，可按类型筛选。

## 已知边界

- 纯前端：无后端、无鉴权，「学员上传」为可调的模拟入口（正常 / 偏航 / 漏标 / 抢航四种特征），上传后走同一条判读链路。
- 观众端只读由视图层强制（无编辑控件），实际部署应由服务端按角色裁剪数据。
- 截图与地图均为 SVG 运行时生成，不依赖外部图片资源。
